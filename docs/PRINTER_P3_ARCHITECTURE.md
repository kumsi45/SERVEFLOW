# Printer P3: Windows local bridge architecture

Status: architecture proposal and safe local foundation. Migration 273 is required and is **not deployed**. No physical transport, pairing endpoint, installer, or Owner Printing UI exists yet. Migrations 271 and 272 remain unchanged.

## Source audit and reuse

The deployed P2 contract is in `supabase/migrations/272_durable_print_job_queue.sql`, with rollback-only audit coverage in `supabase/audits/printer-p2-*.cjs`. The five P2 tables are `print_queue_activations`, `print_agents`, `print_jobs`, `print_job_order_items`, and `print_job_attempts`. Migration 272 is the only job queue; P3 must consume it.

Migrations 207, 208, 210, and 211 supply tenant-scoped `business_printers`, `printer_connections`, `printer_capabilities`, `printer_station_mappings`, `printer_templates`, `printer_test_runs`, `business_printing_settings`, `get_staff_print_runtime`, and owner printer configuration. P2 snapshots the selected printer and template into each job. `printer_connections` supports `network_host inet` with a configurable port, and `usb` with vendor/product IDs and `connection_options`. It has no authoritative installed Windows queue name field; a validated option or dedicated field is needed before spooler support. `printer_capabilities` can hold capability flags, but no bridge consumes them. `printer_test_runs` is a status record, not a durable test job. Templates are metadata; P2 includes their snapshot but no renderer executes it. Never execute arbitrary template text or `connection_options` as commands.

`src/core/printing-payment/runtime.ts` contains browser-side payload helpers and `PayloadOnlyPrinterService`, whose enqueue methods throw. Its `routeKitchenOutput` relies on stored `status='online'`; that is not physical health. `printingRuntimeService.ts` prepares routing but does not dispatch. The Cashier final bill still opens browser `window.print()`. The current Owner Settings component exposes payment configuration, not a Print Bridge pairing UI. The root `package.json` and `tsconfig.json` are for the React/Vite browser application. Existing Supabase Edge Functions, especially `manage-staff`, establish a backend-only Auth Admin pattern. There is no viable Node, Electron, Windows service, or native printer runtime to reuse.

## Exact P2 agent contract

| Surface | Effective behavior from Migration 272 |
| --- | --- |
| Registration | `register_print_agent(uuid,uuid,text)` is service-role-only. Its Auth user must not be staff; `print_agents.auth_user_id` is globally unique. Revocation is service-role-only through `revoke_print_agent(uuid)`. P2 does not provision an Auth user or credentials. |
| Identity | Queue RPCs derive the agent from `auth.uid()`, `enabled`, and `revoked_at`. An agent cannot provide an arbitrary agent UUID to claim work. |
| Claim | `claim_print_jobs(uuid,integer,integer)` permits limit 1–50 and lease 15–300 seconds. It reclaims expired leases, uses `FOR UPDATE SKIP LOCKED`, and takes only pending automatic jobs with non-null `target_printer_id` and due `available_at`. It returns `job_id`, `attempt_id`, `attempt_number`, `job_type`, `printer_purpose`, `target_printer_id`, `payload_version`, `template_id`, `template_version`, immutable `payload`, and `claim_expires_at`. A claim inserts one `print_job_attempts` row and updates agent `last_seen_at`, even if the result is empty. There is no printer-affinity filter. |
| Connection | `get_claimed_print_job_connection(uuid)` returns an active configured connection only while the caller's agent owns an unexpired claim in its restaurant. Its result includes network host/port or USB metadata and `connection_options`. No connection row means no transport. |
| Acknowledgement | `acknowledge_print_job(uuid,uuid,text,text,text,integer)` accepts `dispatched`, `retryable_failure`, or `terminal_failure`; retry delay 5–3600 seconds. It locks the job and verifies current agent, attempt, and unexpired lease. Dispatch means reported transport/spooler acceptance, with `paper_output_confirmed=false`; it is not proof of paper output. Retryable failure returns the job to pending with `available_at`; terminal failure leaves it failed. Attempts record all outcomes. |
| Job identity | Kitchen and receipt jobs use immutable version-1 payloads and automatic keys. Manual reprints require an authorized staff actor, a reason, and a dispatched/failed original; they copy the snapshot into a new audited job with `original_job_id`. `dispatch_mode='on_demand'` requires authorized `request_print_job_dispatch(uuid)`. The bridge must never print unclaimed or on-demand-pending jobs. |
| Payload | Kitchen schema `serveflow.kitchen_ticket.v1` contains restaurant, order, invoice, station, batch key, creator, eligibility time, items and optional template; no financial fields. Receipt schema `serveflow.receipt.v1` contains paid invoice totals and line prices. `payload_version=1` is mandatory for the initial renderer. The item relation preserves exact source IDs and line order. |

## Runtime decision

**Primary architecture:** a bundled Node worker installed as a Windows Service, plus a small separate setup/control UI. The installer includes the pinned Node runtime and a signed native Windows helper for RAW spooler and Credential Manager calls. Staff install a signed `ServeFlow Print Bridge Setup.exe`; they do not install Node, run npm, or edit credentials. The service is delayed auto-start, runs under a dedicated least-privilege service account, depends on the Print Spooler only for installed-printer jobs, and uses Service Control Manager recovery. The setup UI pairs with an owner and configures printers; it is not the print loop. No website needs to remain open.

| Option | Assessment |
| --- | --- |
| Standalone Node service requiring local Node | Good development runtime and low resource use; bad staff installation and version drift. |
| Single packaged Node executable | Convenient distribution, but native spooler/Credential Manager bindings, updates, and service lifecycle need validation. Packaging alone does not provide auto-start. |
| Electron tray app | Easy interactive setup; heavier RAM, session-dependent printing, and poorer unattended reboot behavior. Keep a small setup UI instead. |
| Windows Service with bundled Node worker | Best unattended recovery and OS printer access, modest resource use, and a clear separation between setup and printing. Installer and code signing add work. |

This is a Windows-first packaging choice, not a commitment to Node-only business logic. Keep the queue protocol, payload parser, document model, and error mapping portable so a future Android agent can use a different service shell. Record a bridge semantic version and supported payload-version set. Sign installer and update packages; use a staged, signed updater with rollback later, and server-side minimum-compatible-version policy. Do not auto-update before the installer and service recovery are certified.

## Pairing and local credentials

The bridge generates a 256-bit random proof secret and asks a backend Edge Function to create a five-minute pairing request. The server returns a short human code and pairing ID. The owner enters the code in a future Owner Settings → Printing → Add Print Bridge flow and explicitly approves **one** restaurant. The Edge Function authenticates the owner JWT, checks active owner membership, and records approval. The bridge redeems using its high-entropy proof, not the short code. The server atomically consumes the approved pairing, creates a dedicated non-staff Supabase Auth identity with a random strong password, registers it through P2's service-only RPC, and returns credentials once over TLS. Auth Admin and elevated keys remain in the backend. Failed or ambiguous redemption needs an idempotent state machine and orphan-user cleanup; never issue a second usable identity from the same proof. Re-pair after a lost one-time response. Expire and rate-limit pairing starts, code attempts, and redemption; audit every transition. Rotate by provisioning a replacement identity, verifying it, then revoking and disabling the old Auth user and refreshing its sessions. Revocation must immediately stop claim/renew/ack paths.

Use Windows Credential Manager generic credentials scoped to the bridge service account with local-machine persistence. Restrict its service identity, credential target and filesystem ACLs. DPAPI user scope is a viable implementation fallback; machine scope alone is too broad for the stored agent password. A JSON config may hold nonsecret restaurant ID, endpoint, and printer assignment, never passwords or refresh tokens. The setup UI hands the one-time credential to the service over an authenticated, ACL-protected local IPC channel. No secret appears in logs, command-line arguments, crash reports, or Owner browser storage. A compromised administrator on the restaurant PC remains able to act as that restaurant's agent until revoked; rotation and audit limit impact.

## Job loop, leases, and delivery

One in-flight job per agent for the first release. On startup authenticate and validate the paired tenant. Poll `claim_print_jobs(restaurant,1,300)` roughly every 3–5 seconds while recent work exists, widening to 15–30 seconds with jitter when idle. On cloud/network errors use exponential backoff with jitter capped around two minutes. Realtime may later wake the poller but never replaces claim RPC authority. On empty claims P2 updates `last_seen_at`; a dedicated heartbeat in 273 carries version and runtime status. A 401 refreshes the agent session once; persistent failure pauses claims and surfaces `AUTH_EXPIRED`. On sleep/reboot, reauthenticate and recheck server ownership; never resume a locally remembered claim or persist a second business queue.

For each claim: verify `payload_version` and schema; build a printer-independent document from the immutable snapshot; fetch the owned connection; validate the exact target printer, transport, capabilities and LAN destination; renew the lease immediately before any physical write; bound the render/transport duration to well below the renewed lease; then send. If renewal or connection lookup fails, **do not send**. Stop on known lease loss. If transport returns acceptance, acknowledge `dispatched`; if it returns a definite pre-acceptance error, map to retryable or terminal. If the outcome is ambiguous (timeout after bytes/spooler submission, process crash after acceptance, lost acknowledgement), log `DELIVERY_UNKNOWN` locally and allow the server lease to expire or handle it through an explicit future adjudication policy. Automatic retry can print a duplicate in that case; P2 gives at-least-once delivery, not exactly-once physical output. A renewed lease prevents normal slow-operation expiry but cannot atomically couple a printer with Postgres. Never claim paper completion.

P2 has no lease-renewal RPC and no pre-dispatch ownership assertion that extends a lease, so Migration 273 is required before physical I/O. `get_claimed_print_job_connection` checks ownership only at its call instant. A wall-clock or local timer check alone cannot close the sleep/network race. The first bridge release must also avoid claiming jobs for inaccessible printers; add agent-printer affinity to claim selection. Multiple agents may share a printer assignment; P2 locks give one active claim. A bridge may own kitchen, bar and cashier printers but sends each job only to its snapshotted `target_printer_id`. A job with no route remains pending and is never falsely dispatched.

## Transports and document rendering

The pure foundation in `print-bridge/src/` converts P2 version-1 snapshots into semantic kitchen and receipt documents and offers a mock transport. A later renderer turns documents into ESC/POS bytes. Width profiles begin at 58 mm (about 32 text columns) and 80 mm (about 48); actual columns depend on printer font and must be calibrated. Preserve line item order and wrap by measured glyph width. Kitchen uses restaurant, KITCHEN TICKET, order/table, eligible time, creator, station, quantities, item names, notes, order note and batch reference. Its model intentionally excludes subtotal, VAT, total, payment and settlement details. Receipt separately uses paid-at, invoice/reference, items with source unit/line prices, source subtotal/tax/service/discount/total and payment method when present. Never recompute authoritative money from display lines. Template metadata is snapshotted but cannot inject commands; only allowlisted renderer options may eventually be honored.

English and Afaan Oromo in the Latin alphabet may use a verified printer code page for supported glyphs, but code-page compatibility must be measured per model. Do not transliterate silently. Amharic requires a raster text path with bundled Ethiopic fonts or a model proven to support it; native ESC/POS text mode is not universally sufficient. Unknown glyphs must produce a visible controlled fallback and a diagnostic, never silently disappear. Raster output costs more bytes/time, so renew the lease before slow rendering/transport and set a strict byte/time budget. A 58/80 mm preview and golden-file tests should cover English, Afaan Oromo diacritics and Amharic.

LAN transport uses the configured `network_host` and `network_port`, typically but not necessarily 9100. Resolve/validate the destination at connection time and after DNS resolution; `inet` hosts are already numeric. Require an allowlisted private or explicitly approved restaurant-local subnet, deny loopback, link-local, multicast, unspecified, metadata/cloud and public destinations by default, and restrict ports to configured printer ports. Do not derive a network address from payload. Use connect, write and overall timeouts; classify connection refusal/unreachable as retryable. A successful TCP write is transport acceptance only.

Windows-installed/USB support should target a selected installed printer **queue name** and use a signed helper calling `OpenPrinter` / `StartDocPrinter` with `RAW` / `WritePrinter` / `EndDocPrinter`. Vendor/product IDs alone do not identify a Windows queue. Add a validated queue-name field or strictly allowlisted connection option in 273, selected from locally enumerated queues during setup. Avoid shell commands, arbitrary executable paths and manufacturer-specific SDKs initially. Spooler acceptance is not proof of physical printing. Test the service account's queue permissions. Use distinct transport timeouts and errors for missing queue, spooler stopped and spooler rejection.

Capabilities live per printer: `supports_cut`, `supports_buzzer`, and reserved `supports_cash_drawer`. Send cut or vendor-verified buzzer commands only when explicitly configured and model-tested; buzzer failure after accepted print is a separate diagnostic, not a failed ticket. Cash drawer control is deferred and must never ride a kitchen ticket. Printer reachability observations are separate from configured state; no stored `business_printers.status='online'` is accepted as proof of readiness.

## Errors, health, logs, and offline behavior

Error codes: `NETWORK_UNREACHABLE`, `CONNECTION_TIMEOUT`, `CONNECTION_REFUSED`, `PRINTER_OFFLINE`, `PAPER_OUT`, `SPOOLER_UNAVAILABLE`, `SPOOLER_REJECTED`, and `AUTH_EXPIRED` are retryable when the operation definitely did not reach the printer. `PRINTER_NOT_FOUND`, `UNSUPPORTED_PRINTER`, `INVALID_PAYLOAD_VERSION`, `RENDER_FAILED`, and `INVALID_DESTINATION` are terminal until configuration/version changes. `LEASE_LOST` means no physical send and no stale acknowledgement. `DELIVERY_UNKNOWN` means possible physical output; never describe it as a definite failure or safe automatic retry. P2 retry delays are 5–3600 seconds; use exponential policy by error class and attempt count, with a cap. Do not send stack traces in RPC messages.

Local structured logs include UTC timestamp, agent/restaurant ID, job/attempt ID, target printer ID, transport, bridge version, duration, outcome and safe error code. Exclude tokens, passwords, full connection options, sensitive receipt contents and stack traces from routine logs. Rotate by size and age with bounded retention and protected ACLs. Health dimensions are bridge heartbeat, agent auth, cloud reachability, configured printer, last reachability probe, last transport acceptance, last error, and evidence timestamp. Owner UI must label stale or unknown observations as such. P2 `print_agents.last_seen_at` is a limited claim-poll signal, not printer health; 273 should add explicit heartbeat/version and per-printer observations.

Internet or Supabase outage leaves server jobs authoritative and pending; the bridge backs off and resumes when connected. Printer outage maps definite failures to retryable attempts with server backoff. If the cloud never received an order during an internet outage, P3 cannot print it or provide offline ordering. The mock transport captures documents and simulates accepted, timeout, offline and retryable outcomes; it is flagged `simulation_only` and must never be packaged/enabled as production physical success.

## Threat model

| Threat | Control |
| --- | --- |
| Stolen short code | Code only locates a request; owner authentication and high-entropy bridge proof are both required. Five-minute expiry, one-time consume, attempt limits and audit. |
| Copied agent credential or compromised PC | Credential Manager/DPAPI, dedicated tenant-only Auth user, short JWT lifetime, fast agent revoke and Auth disable/session invalidation, logs and rotation. Local administrator compromise cannot be fully prevented. |
| Tenant A accessing B, forged agent UUID | P2 resolves `auth.uid()` to one tenant and checks lease; 273 RPCs must repeat those checks. Edge Function must derive owner from verified JWT, never a supplied user ID. |
| Replay or old bridge | Pairing compare-and-swap state, proof hash, expiry, attempt ID checks, revoked-agent checks on every queue RPC, version floor. |
| Malicious connection metadata or LAN address | Strict schema/option allowlist, selected installed queue names, private-subnet destination validation at use time, no command execution or payload-directed sockets. |
| Credential leakage in logs | Redacted structured logger, bounded retention, ACLs, no raw options or auth responses. |

## Candidate Migration 273 contract — review before SQL/deployment

Migration 273 is necessary for secure pairing, safe renewal, agent affinity and truthful health. Its candidate contract is:

1. `print_bridge_pairings`: `id uuid` PK; `code_digest bytea` unique; `proof_digest bytea` unique; `status text` constrained to `pending/approved/redeeming/consumed/expired/cancelled/failed`; `approved_restaurant_id uuid` tenant FK; `approved_by_user_id uuid` Auth FK; `agent_id uuid` FK; `agent_auth_user_id uuid` Auth FK; `created_at`, `expires_at`, `approved_at`, `redeeming_at`, `consumed_at`, `cancelled_at` timestamps; bounded `bridge_name` and `failure_code`. Check state/timestamp shapes. No plaintext code, proof or credential columns. Force RLS; no anon/authenticated table grants; service role only. Expiration is checked in every transition, not dependent on a cleanup worker. Edge-only code digest uses a server-side HMAC secret; high-entropy proof uses SHA-256.
2. `print_bridge_pairing_events`: append-only ID, pairing ID, restaurant ID when approved, actor Auth ID when applicable, event type, UTC timestamp, safe reason/IP hash. Service role only, forced RLS, no secrets. Index by pairing/time and restaurant/time. Never delete audit events as part of normal expiration.
3. Service-only transition RPCs: `begin_print_bridge_pairing(code_digest bytea, proof_digest bytea, bridge_name text, ttl_seconds integer)` creates a bounded pending row after backend rate limiting; `approve_print_bridge_pairing(pairing_id uuid, code_digest bytea, restaurant_id uuid, owner_user_id uuid)` checks an active owner membership inside SQL and atomically moves pending to approved; `begin_print_bridge_redemption(pairing_id uuid, proof_digest bytea)` atomically moves approved to redeeming and returns only tenant/name to the trusted Edge Function; `complete_print_bridge_redemption(pairing_id uuid, auth_user_id uuid)` calls P2 `register_print_agent`, moves to consumed, and records an event in one transaction. Add `fail_print_bridge_redemption` and cancellation with restricted state transitions. Repeated calls must not create a second agent. These RPCs are granted to `service_role` only, fixed `search_path`, and the Edge Function must authenticate both owner and bridge proof. Auth user creation/cleanup is outside the DB transaction and needs explicit compensation and orphan audit.
4. `print_agent_printers(restaurant_id, agent_id, printer_id, enabled, created_at)` with composite tenant FKs to `print_agents` and `business_printers`, unique `(agent_id,printer_id)`, forced RLS and service-only writes. Replace P2 `claim_print_jobs` in 273 to require an enabled assignment for `target_printer_id` while preserving all P2 claim, retry and attempt semantics. No assignment means no claim. The installer initially assigns all selected reachable printers to one bridge; multiple bridges may share an assignment. An agent must not use the absence of an assignment as permission to claim all.
5. `renew_print_job_lease(job_id uuid, attempt_id uuid, requested_seconds integer) returns timestamptz`: authenticated agent only, derived from `auth.uid()`, lock job and attempt, require same restaurant/agent, `status='claimed'`, matching current attempt, and unexpired lease. Bound requested extension to 15–300 seconds and total claim lifetime to 10 minutes. Set both `print_jobs.claim_expires_at` and `print_job_attempts.lease_expires_at` to the same server-clock expiry; return expiry. No new attempt or status change. A revoked agent cannot renew. Grant execute only to authenticated/service role; no direct table grants.
6. `heartbeat_print_agent(restaurant_id uuid, bridge_version text, runtime_status text)` authenticated agent only; bounded version string and status enum; updates `last_seen_at` and new `bridge_version`, `last_heartbeat_at`, `runtime_status` columns on `print_agents`. Heartbeat is an observation, not printer readiness. Add `print_printer_observations` keyed by `(restaurant_id, agent_id, printer_id)` with composite tenant FKs, `observed_at`, `reachable`, `last_transport_accepted_at`, and `last_error_code`; force RLS and deny direct anon/authenticated access. `report_print_printer_observation(printer_id uuid, reachable boolean, transport_accepted boolean, error_code text)` derives the agent from `auth.uid()`, requires an enabled printer assignment, uses server timestamps, and never overwrites configuration status. Only authenticated agents and service role execute it. Reachability means a recent probe, not paper success.
7. Add `windows_queue_name text` to `printer_connections`, nullable and bounded, applicable only to `usb`/installed queue mode; one validated local queue selection per active connection. Keep existing network host/port and tenant FKs. The bridge must revalidate against locally enumerated queues and must never execute this text. If the field is deferred, Windows spooler support remains blocked.
8. A durable test-print job cannot be represented by P2's required order/invoice and two job types without forging business records. Plan a subsequent reviewed migration that extends P2 `print_jobs` with a test job type, nullable order/invoice only for that type, a test payload schema, and links to `printer_test_runs`. Do not create a competing queue or mark a visual preview as passed.

Review gates before writing/applying executable 273 SQL: concurrency and replay tests for pairing transitions; Auth Admin failure compensation; exact grants/RLS/tenant FKs; regression of P2 claim/ack and historical activation; lease-renew versus reclaim races; compatibility with already registered agents; schema drift check on installed-queue metadata; no destructive testing on live operations. This document defines the candidate contract; it is not an executable migration or approval to deploy it.

## Test and certification sequence

Build the pure parser/document model and mock tests first. Next review and implement Migration 273 plus pairing Edge Function in an isolated backend, including malicious-owner, replay, expired code, partial Auth failure, revoke and rotation cases. Then implement service auth/credential storage, safe polling/renewal, renderer, LAN transport, spooler helper, installer and signing. Add unit/golden tests for version parsing, 58/80 mm wrapping, multilingual raster fallback, money source preservation and redacted logs; transport tests for socket success/refusal/timeout and RAW spooler acceptance/failure; service tests for sleep, restart, auth expiry, lease loss, multiple printers/agents, offline recovery and credential persistence. Ship no mock transport in production mode.

Physical certification needs at least one ESC/POS LAN printer and one Windows-installed USB thermal printer for both transports, with actual 58/80 mm and multilingual samples. On a Windows test machine certify install/pair/revoke/rotate, selected printer and durable test print, Cashier and Waiter tickets, unpaid QR silence and paid QR release, additions, receipt, paper-out where detectable, printer offline/reconnect, internet outage/recovery, Windows reboot, duplicate-risk cases, cutter and model-supported buzzer. Record spooler acceptance separately from observed paper output. No physical certification is claimed by this architecture phase.
