Prior PASS results for claim atomicity remain valid within their tested scope.

The hosted JWT/CORS matrix still needs a separately identified nonproduction Supabase project with disposable Auth/restaurant data and dedicated Upstash credentials: allowed and disallowed Owner origins across OPTIONS/POST and gateway-added headers; missing, malformed, expired, valid and cross-tenant Owner JWTs; public start/redeem without gateway JWT; and missing/valid reconciliation maintenance authentication. Review the target before any deployment or test that changes it. No such test was attempted here.

Production secret inventory to verify before controlled deployment review: `SUPABASE_URL` and public `SUPABASE_ANON_KEY`; server-only `SUPABASE_SERVICE_ROLE_KEY`; `PRINT_BRIDGE_DIGEST_KEYS` with old-version grace for outstanding five-minute artifacts; independent stable `PRINT_BRIDGE_RATE_KEY`; `PRINT_BRIDGE_EMAIL_DOMAIN` and exact `PRINT_BRIDGE_OWNER_ORIGIN`; `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`; and scheduler-only `PRINT_BRIDGE_MAINTENANCE_KEY`. No rotation was performed here.

Before scheduling reconciliation, assign an operator and alert destination; test each run's success/failure, page on the proposed 30-minute schedule/cleanup failure and 10-minute Redis-503 threshold, and ticket retained orphans.
